# processor

Надёжный планировщик периодических задач на Go с гибкой настройкой, повторными попытками, контролем конкурентности и встроенными метриками для Prometheus. Подходит для фоновых воркеров в микросервисной архитектуре.

## 📦 Установка

```bash
go get github.com/s-ilyin/processor
```

## 🚀 Быстрый старт
```go
    cfg := DefaultConfig()
    cfg.Name = "TEST-PROCESSOR"

    // Обработчик задачи
    simpleHandler := func(ctx context.Context) (wait bool, err error) {
        // Здесь ваша бизнес-логика.
        // bool указывает, были ли обработаны сообщения.
        // Если false – следующая задача запустится немедленно.
        // Если true – будет ожидаться следующий интервал.
        return false, nil
    }

    p := processor.NewPeriodTask(cfg, handler)

    p.Start()
    defer p.Stop()
```

## 🔄 Механизм работы

- При старте задача запускается **немедленно** (таймер с нулевой задержкой).
- После каждого выполнения:
  - Если хендлер вернул `(false, nil)` – следующая задача запускается **без ожидания** (немедленный перезапуск).
  - Если хендлер вернул `(true, nil)` – следующая попытка планируется через `Interval`.
- Если семафор конкурентности заполнен – новые попытки не запускаются, таймер перезапускается, пока не освободится место.
- Паники в хендлере перехватываются, задача считается завершённой с ошибкой, планировщик продолжает работу.
- Остановка через `Stop()` дожидается завершения всех текущих задач.

## 🧩 Вспомогательные функции (опции)

Пакет предоставляет утилитарные функции для преобразования стандартных обработчиков (возвращающих только `error`) в формат, ожидаемый планировщиком (`func(ctx context.Context) (bool, error)`). Эти функции помогают управлять поведением `wait` без необходимости явно прописывать логику в каждом обработчике.

| Функция | Сигнатура | Описание |
|---------|-----------|----------|
| `OnlyErrorWait` | `func(f func(context.Context) error) func(context.Context) (bool, error)` | Возвращает `wait=true`, только если `f` вернула ошибку. При успешном выполнении `wait=false` (немедленный перезапуск). |
| `AlwaysWait` | `func(f func(context.Context) error) func(context.Context) (bool, error)` | Всегда возвращает `wait=true` независимо от результата `f`. Подходит для случаев, когда нужно строго соблюдать интервал. |
| `SkipWait` | `func(f func(context.Context) error) func(context.Context) (bool, error)` | Всегда возвращает `wait=false` — следующая задача запускается сразу после завершения, независимо от наличия ошибок. |

**Пример использования:**

```go
// Обработчик без учёта wait
simpleHandler := func(ctx context.Context) error {
    // логика...
    return nil
}

// Вариант 1: ждём только при ошибке
handler1 := processor.OnlyErrorWait(simpleHandler)

// Вариант 2: всегда ждём интервал
handler2 := processor.AlwaysWait(simpleHandler)

// Вариант 3: никогда не ждём
handler3 := processor.SkipWait(simpleHandler)

p := processor.NewPeriodTask(cfg, handler1) // используем любой из них
```

## 📊 Метрики Prometheus

| Метрика | Тип | Лейблы | Описание |
|---------|-----|--------|----------|
| `processor_tasks_total` | Counter | `name`, `is_success`, `is_retry` | Общее количество выполненных задач с разбивкой по результату и признаку повторной попытки |
| `processor_semaphore_used` | Gauge | `name`, `state` | Количество занятых слотов семафора (state="used") для каждого процессора |
| `processor_task_duration_seconds` | Histogram | `name` | Время выполнения обработчика (без учёта ожидания семафора) |
| `processor_wait_duration_seconds` | Histogram | `name` | Время ожидания семафора перед запуском задачи |
| `processor_total_duration_seconds` | Histogram | `name` | Полное время выполнения задачи (включая ожидание семафора и все повторные попытки) |

**Примечания:**
- Все метрики регистрируются автоматически в глобальном реестре Prometheus при создании процессора.
- Лейбл `name` соответствует полю `Name` в конфигурации.
- Гистограммы используют стандартные бакеты Prometheus (`prometheus.DefBuckets`).
